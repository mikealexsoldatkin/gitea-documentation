# Это описание страницы "tree".

Confluence оперирует лишь одним типом объектов - "Страница"
Для того, чтобы создать иерархию, одна страница помечается как родительская, вторая как дочерняя.

В файловой системе ОС типа объектов два - "файл" и "каталог"
Для создания иерархии используются каталоги. Пометить один файл, как родительский, а другой дочерний, невозможно.

Поэтому для того, чтобы построить соответствие, используются следующие подходы (настраивается параметром `contentLookupMode` в `application.yml`)

## contentLookupMode = SAME_DIR_FILE_NAME (основной)

1. Если создан каталог, то при рендеринге в confluence каталог будет преобразован в пустую страницу.
2. Если рядом с каталогом есть файл `*.md` с таким же названием (если отбросить расширение `*.md`), то содержимое страницы, ассоциированной с каталогом будет заменено на содержимое этого файла

### В нашем примере:

Структура файловой системы:
- demo.md
- tree.md
- tree
  - childpage.md
  - index.md
- Название файла на кириллице.md

Структура в confluence:
- Demo-страница                 <!-- название изменено через PAGE_OPTIONS -->
- Страница с деревом            <!-- название изменено через PAGE_OPTIONS -->
  - childpage
  - index
- Название файла на Кириллице

## contentLookupMode = HTML_LIKE

1. Если создан каталог, то при рендеринге в confluence каталог будет преобразован в пустую страницу.
2. Если внутри каталога есть файл `index.md`, то содержимое страницы, ассоциированной с каталогом будет заменено на содержимое этого файла

### В нашем примере:

Структура файловой системы:
- demo.md
- ~tree.md~     <!-- Этот файл на самом деле не учитываем, если его оставить, то движок ругнется на два одинаковых названия -->
- tree
  - childpage.md
  - index.md
- Название файла на кириллице.md

Структура в confluence:
- Demo-страница                 <!-- название изменено через PAGE_OPTIONS -->
- tree
  - childpage
- Название файла на кириллице
